The pass is captured one frame at a time at the chosen frame rate, so it is both the right length and frame-exact — provided the machine paints at least that fast. The counter shows frames written and fps painted; if painting drops below the capture rate the file runs long, so turn off Bloom or the Comoving grid. The Format button lists what this browser can actually encode, best first, and the grey text beside it is the exact codec string it will use. MKV and MP4 both hold H.264, so they remux to MP4 losslessly; WebM has to be re-encoded:
ffmpeg -i BigCrunch_<pass>.mkv -c copy BigCrunch.mp4  (from MKV, instant)
ffmpeg -i BigCrunch_<pass>.webm -c:v libx264 -crf 16 -pix_fmt yuv420p -r 30 BigCrunch.mp4  (from WebM)
An MP4 written by the browser is fragmented; if Camtasia refuses it, ffmpeg -i in.mp4 -c copy out.mp4 rewrites the index without re-encoding.
